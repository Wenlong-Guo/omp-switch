# 测试策略

## 测试目标

编写 **200 条**测试用例，覆盖 Rust 后端（DAO / Service / Command）和 React 前端（组件 / Hooks / E2E），确保 MVP 功能稳定可靠。

## 测试框架

| 层级 | 框架 | 用途 |
|------|------|------|
| Rust 单元/集成 | `cargo test` + `mockall` + `tempfile` + `tokio-test` | 后端逻辑测试 |
| React 组件 | `vitest` + `@testing-library/react` + `@testing-library/jest-dom` | UI 渲染与交互 |
| React Hooks | `vitest` + `@testing-library/react-hooks` | 状态逻辑测试 |
| E2E / 集成 | `vitest` + 模拟 Tauri invoke | 端到端链路测试 |

## 用例分布（200 条）

| 层级 | 数量 | 覆盖范围 |
|------|------|----------|
| **Rust DAO 单元测试** | 40 条 | provider_dao CRUD、settings_dao 单条读写、sync_dao changelog |
| **Rust Service 单元测试** | 50 条 | provider_service 校验/切换、config_writer 原子写入、config_reader 回填、file_watcher 事件、sync_service WebDAV 模拟 |
| **Rust Commands 集成测试** | 30 条 | IPC 命令端到端（创建→读取→更新→删除→切换） |
| **React 组件测试** | 50 条 | ProviderCard / ProviderForm / ModelEditor / RoleEditor / SyncConfigForm 渲染、交互、表单校验 |
| **前端 Hooks 测试** | 20 条 | useProviders / useSettings / useSync 状态流、错误处理 |
| **E2E / 集成测试** | 10 条 | 完整链路：创建 provider → 保存 → 写出 YAML → 切换默认 → 读取 settings.json |

## 关键测试场景

| 场景 | 类型 | 验证点 |
|------|------|--------|
| 跨平台路径解析 | Rust | macOS/Win/Linux 上 `~/.omp/agent/` 和 `~/.omp-switch/` 路径正确 |
| 原子写入中断 | Rust | 写入中断后原文件不损坏，temp 文件清理 |
| 文件监听外部编辑 | Rust + React | vim 编辑 YAML 后前端自动刷新 |
| WebDAV 上传下载 | Rust | 模拟 WebDAV 服务器，验证 PUT/GET/PROPFIND |
| WebDAV 双向冲突 | Rust | 本地和远程同时修改，冲突检测正确 |
| API Key 加密 | Rust | 加密存储，内存中不泄露明文 |
| 表单必填校验 | React | 缺失必填项时显示错误并阻止提交 |
| URL 格式校验 | React | 非法 URL 格式提示 |
| API 类型枚举 | React | 非法 api 类型无法选择 |
| 负数 cost | React | 输入负数时提示错误 |
| 空 provider 列表 | React | 空状态显示引导 |
| 超长 model id | React + Rust | 超长 ID 正常处理不崩溃 |
| 特殊字符 headers key | React + Rust | 含空格/特殊字符的 key 正常保存 |

## 测试命令

```bash
# 后端测试
cd src-tauri && cargo test --all

# 前端测试
npm run test

# 前端测试（带覆盖率）
npm run test:coverage

# 全量测试
npm run test:all
```
