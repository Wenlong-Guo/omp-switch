# 技术架构

## 项目概述

omp-switch 是 oh-my-pi 的桌面配置管理器，基于 Tauri 2 + React + SQLite 构建，支持跨平台（macOS / Windows / Linux）和 WebDAV 多端同步。

## 技术栈选型

| 层级 | 技术 | 版本 | 理由 |
|------|------|------|------|
| 桌面框架 | Tauri | 2.x | Rust 原生后端、跨平台、体积小、性能高 |
| 前端框架 | React | 18 | 组件化、生态成熟、与 cc-switch 一致 |
| 构建工具 | Vite | 6.x | 极速 HMR、Tauri 官方推荐 |
| 类型系统 | TypeScript | 5.7 | 全链路类型安全 |
| 样式方案 | TailwindCSS | 4.x | 原子化 CSS、快速开发 |
| 组件库 | shadcn/ui | latest | 不锁样式、基于 Radix、可深度定制 |
| 状态管理 | Zustand | 5.x | 极简、无样板 |
| 表单校验 | react-hook-form + zod | latest | 类型安全、性能优 |
| 本地数据库 | SQLite (rusqlite) | 0.34+ | SSOT、事务安全、cc-switch 已验证 |
| 同步协议 | WebDAV (reqwest) | HTTP | 支持坚果云、NextCloud 等 |

## 设计原则

1. **SSOT（单一数据源）**：所有配置以 SQLite 为唯一真相源，YAML/JSON 仅为导出格式
2. **双向同步**：SQLite ↔ 文件系统 ↔ WebDAV，任何一端变更自动同步到其他端
3. **原子写入**：文件操作使用 temp + rename 模式，防止写入中断导致配置损坏
4. **离线优先**：SQLite 本地始终可用，WebDAV 同步失败仅标记状态不影响使用
5. **跨平台一致**：路径、文件监听、托盘菜单全部通过 Tauri API 抽象

## 数据流

### 写入流（前端 → SQLite → 文件 → WebDAV）

```
用户编辑 Provider → 前端表单校验 → invoke save_provider
  → Rust Command → ProviderService 校验 → ProviderDao.upsert(SQLite)
  → ConfigWriter → 原子写入 models.yml
  → 记录 changelog → SyncService 触发 WebDAV 上传（如启用）
```

### 读取流（文件 → SQLite → 前端）

```
App 启动 → ConfigReader 读取 models.yml / settings.json → 回填 SQLite
  → 前端 Dashboard 查询 SQLite → 渲染 Provider 列表
```

### 外部变更流

```
用户 vim 编辑 models.yml → FileWatcher 检测 → ConfigReader 解析差异
  → 差异回填 SQLite（冲突时保留 GUI 未同步的变更）
  → 发送 config:changed 事件 → 前端自动刷新
```
